# أتمتة ما بعد البيع — أساس المعاينة

هذه المرحلة تعرض العملاء والعروض المقترحة فقط. لا ترسل واتساب، ولا تنادي API سلة، ولا تغيّر عامل تذكيرات السلات.

## التجهيز

1. شغّل `crm-postpurchase.sql` في Supabase SQL Editor. يحتاج جداول الطلبات والعملاء الموجودة، ومزامنة سلة السابقة (`crm_source_at`)، وجدول إلغاء اشتراك واتساب.
2. افتح `/dashboard#postpurchase`.
3. عرّف منتجًا مشتَرى ومنتجًا مكملًا. القائمة المقترحة مستخرجة من الطلبات المحلية لآخر 30 يومًا، وليست جميع منتجات المتجر. يمكن إدخال منتج غير موجود فيها يدويًا.
4. أدخل موديل الجهاز بدقة ومحتويات كل بكج كاملة. عند وجود موديلات مختلفة لنفس المنتج، عرّف كل SKU على حدة؛ المنتج متعدد الموديلات لا يُربط كأنه موديل واحد.
5. أضف قاعدة تربط المنتج المشتَرى بالعرض، ثم راجع المعاينة.

## ما يعمل الآن

- جداول خاصة لا يستطيع anon أو authenticated الوصول إليها مباشرة. الواجهة تعمل عبر API الإدارة المحمي.
- تعديل التعريفات والعروض وإيقاف قواعد المعاينة.
- إعدادات محفوظة: 7 أيام، 11:00 و17:00 و20:00 بتوقيت السعودية، 10 عملاء كحد أقصى، 14 يومًا بين العروض، ميزانية مستقبلية لفحص المخزون 300 طلب شهريًا.
- ملاحظة انتقال الطلبات إلى delivered بعد بدء النظام؛ الساعة تبدأ عند رصد الانتقال محليًا، ولا نقترض تاريخ تسليم سابقًا من تاريخ إنشاء الطلب. السجلات المستوردة بحالة delivered لا تُسجّل كتسليم جديد؛ الطلبات القديمة لا يُفترض لها تاريخ تسليم. التحديث المتكرر لنفس حالة التسليم لا يعيد بدء المؤقت.
- معاينة حتى 200 طلب مسلّم من آخر 30 يومًا، وعرض حتى 100 مطابقة؛ أرقام الصفحة تخص هذه العينة المحدودة.
- استبعاد في المعاينة عند إلغاء الاشتراك أو شراء لاحق أو امتلاك مكوّن من العرض أو اختلاف الموديل أو وجود منتج غير معرّف بالطلب.
- لا نفترض توفر المخزون: المطابقة التي حان موعدها تظهر «فحص المخزون والقالب مطلوب».

## ما يحتاج المرحلة التالية

- مراجعة المنتجات الفعلية والموديلات وSKU ومحتويات البكجات.
- قالب تسويقي سعودي معتمد في Etisalna، بمتغير اسم العميل واسم العرض ورابط المنتج وزر إلغاء الاشتراك. قالب السلة الحالي ورابط mtjr.at للسلة لا يعاد استخدامهما تلقائيًا للمنتجات.
- فحص مخزون المنتجات والنسخ المقترحة فقط قبل الدفعة، مع عداد وميزانية محدودة؛ لا فحص كل دقيقة ولا استيراد تاريخي.
- طابور إرسال مع قفل ومنع التكرار واحتساب حد الدفعة وفاصل 14 يومًا وإعادة التحقق من الشراء/إلغاء الاشتراك قبل الإرسال.
- إدخال بيانات المرتجعات والشكاوى كإشارات منع موثوقة. لا يوجد في هذه المرحلة كشف تلقائي للشكاوى.
- دمج عامل الدقيقة الموجود مع قواعد عادلة بين تذكيرات السلة وما بعد البيع، وإرسال واحد في الدقيقة.
- حالات قبول المزود والتسليم الفعلي منفصلة، وقياس النقر والشراء اللاحق بعد إعداد التتبع.

حتى تكتمل هذه المتطلبات لا يوجد زر لتفعيل الإرسال، ولا يمكن تفعيله عبر API هذه الصفحة.
