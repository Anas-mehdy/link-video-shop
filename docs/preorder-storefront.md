`/preorder-preview.html` is a standalone visual simulation for product, preorder-only cart, mixed cart and ready-only cart. It stubs all its API/cart reads locally and performs no purchases. These fixtures are not a native Salla checkout test. Actual schedule text on the store is read from the current database batch through `/api/protection-feed?mode=preorders&ids=318533359&preview=1`. This reuses an existing function, no new runtime function or paid dependency. The feed exposes only product name/color, status, dates and revision; no reservations, customers, quantities or secrets. Draft data is excluded without preview. The flag is a display mode, not an authorization mechanism; the exposed dates are public-safe.

The widget inserts a disclosure before the product form and before an observed cart-summary/checkout anchor. It does not replace native price, stock, button logic or SDK methods. On cart pages it checks exact `product_id`/`product.id`; cart line IDs cannot trigger it. Ready-only carts do not query the preorder feed. Local SDK cart events and debounced DOM redraws refresh the reminder; schedules are reused for 30 seconds within the page to avoid repeated server reads. Page visibility refreshes recheck dates. No polling or outbound tracking is used.

The acknowledgement checkbox gates recognized DOM add/checkout controls, including composed web-component click paths. It is **not server enforcement, a persisted consent record, or a guarantee of covering every accelerated checkout/custom theme control**. JavaScript-disabled paths and native checkout disclosure still require review. It does not change shipping rates or split orders. Cart errors never classify an unrelated ready-only cart as a preorder. For recognized preorder carts, missing schedule data shows an error reminder rather than silently asserting dates.
