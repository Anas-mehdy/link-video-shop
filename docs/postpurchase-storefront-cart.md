# تجربة الإضافة الجماعية داخل المتجر

السكربت complete-storefront.js يُحمّل في قسم HTML بالفيديو شوب في نسخة ملاك تجارب 1409940314 فقط. لا يعمل إلا عند وجود `#link-complete=<encrypted-token>`؛ الصفحة الرئيسية العادية لا تتغير. يحتاج تحميله عبر loader يستمع أيضًا لتغير hash. لم تُعدّل النسخة الأساسية 603175051.

افتح معاينة ملاك تجارب من إعدادات النسخة أولًا، ثم من الداشبورد أنشئ صفحة الطلب وافتح «تجربة الإضافة داخل المتجر». رابط معاينة سلة من واجهة المزود يعتمد على نسخة المعاينة المختارة؛ لا نفترض أن نسختها صحيحة بدون فتح النسخة المطلوبة أولًا.

الصفحة الديناميكية تُعرض داخل iframe في المتجر. زرها «أضف اختياراتي للسلة» يرسل IDs والكميات فقط إلى الجسر. يراجع الجسر المنتجات عبر الاستجابة المحفوظة ويعرض نافذة واحدة لكل خيارات المنتجات مستخدمًا salla-product-options؛ يستدعي reportValidty وhasOutOfStockOption وgetSelectedOptionsData قبل أي إضافة. ثم يستدعي salla.cart.addItem بالتسلسل للقطع المختارة، وينتقل إلى /cart عند نجاح الجميع. التصفح واختيار الخيارات والإضافة يستخدمان واجهة المتجر؛ لا استدعاء Merchant API لهذه الخطوات.

تُقيد رسائل iframe بـ origin الصحيح وcontentWindow ومعرّف طلب عشوائي. لا تُقبل IDs خارج قائمة الرابط. تُسجّل حالة كل إضافة في sessionStorage قبل الاتصال. نجاح القطعة يُحفظ ولا يعاد إضافته عند إعادة محاولة الدفعة، والمهلة أو الرد غير الواضح يُحفظ unknown ويتوقف التسلسل. يُعرض رابط السلة للتحقق. الاختيارات الخاطئة تُمنع قبل أي إضافة، ورفض واضح لقطعة لا يلغي القطع الناجحة. الكميات المقبولة 1 إلى 10، والدفعة 1 إلى 20 منتجًا. كل هذه الحالات خضعت لاختبارات بمزود محاكى، وليست إثباتًا لتجربة فعلية على سلة.

الصفحة المستقلة على Vercel تبقى لعرض الاقتراحات؛ الإضافة تعتمد وجود الجسر داخل المتجر. بعد نجاح تجربة سلة يُنقل تحميل الجسر للنسخة الأساسية، وتُغيّر وجهة رابط الحملة للمتجر. لم يُفعّل إرسال العملاء أو يُغيّر قالب واتساب في هذه المرحلة.
