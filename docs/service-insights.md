# خدمة العملاء: من المحادثة إلى تحسين المتجر

نسخة الأساس لهذه المرحلة: `97ac65bb12fb28c612d78b6f8202acbdd95d9dfd`، بعد نشر تحسينات UX. التعديلات الجديدة محلية، ولم تُنشر.

## طريقة الاستخدام

افتح «إحصائيات وتحسينات المتجر» في قسم خدمة العملاء، ثم اختر الفترة. تظهر تغطية التحليل، تليها قائمة أولويات التحسين. موضوع السؤال والعائق الفعلي ونتائج سلة داخل تفاصيل تُفتح عند الحاجة، دون شبكة بطاقات أو تغيير الرئيسية.

الضغط على أي عدد أو نتيجة يعرض محادثاتها الداعمة في القائمة الحالية، مع التنقل السابق/التالي وفتح الرحلة. «العودة إلى القائمة الأصلية» يستعيد الفلتر وموضع التمرير. على الهاتف يحفظ زر الرجوع قائمة الحالات الداعمة، ومنها يمكن الرجوع للقائمة الأصلية.

داخل الرحلة تظهر نتيجة سلة مستقلة عن ملاحظات التحليل. الرسائل الداعمة لنتيجة الطلب وللتصنيفات تفتح بواسطة معرّف الرسالة الثابت. إذا كانت الرسالة خارج آخر 100 رسالة، يظهر المقتطف المحفوظ وتوضيح عدم توفر الرسالة؛ لا تُستخدم أرقام الرسائل القديمة للقفز إلى رسالة مختلفة.

## ما الذي يدخل الحساب؟

- الفترة تشمل أيام السعودية من 00:00 إلى 23:59:59، وتتوقف عند الآن. الحد الأقصى 93 يومًا.
- المقام هو **المحادثات المختلفة التي وصل منها نص أو حدث عميل في الفترة**، وليس عدد التحليلات أو الرسائل أو العملاء المشترين.
- البسط هو المحادثات التي لها **تحليل مكتمل محفوظ حتى الآن**. كل محادثة تدخل مرة واحدة باستخدام آخر تحليل مكتمل، دون جمع نسخ قديمة. هذه نسبة وجود تحليل محفوظ، وليست تأكيدًا أن كل الرسائل الحديثة حُللت أو مقياس جودة.
- التصنيفات تُحتسب فقط إذا كان لها رمز معروف، ومعرّف رسالة ومقتطف محفوظ ووقت داخل الفترة. موضوع السؤال والعائق يحتاجان رسالة عميل؛ التدريب يحتاج رد موظف مؤكد.
- قد تحمل المحادثة أكثر من تصنيف؛ لذلك لا تجمع صفوف التصنيفات كمجموع جديد للمحادثات.
- التحليلات النصية القديمة تدخل في عدد التحليلات المحفوظة، وتظهر منفصلة تحت «غير مصنّفة». لا تحليل كلمات مفتاحية ولا تخمين لتوزيعها على الفئات. تبقى ملاحظاتها الأصلية قابلة للفتح.
- لا تُعرض نسبة تغطية كاملة عند نقص السجل، ولا تصبح البيانات غير المتاحة صفرًا أو نسبة 100%.

## التصنيفات الثابتة

| النوع | الرموز والمعاني |
| --- | --- |
| موضوع السؤال | `fit` التوافق والمقاس، `product` المواصفات، `price` السعر والعروض، `checkout` الدفع، `shipping` الشحن، `order` متابعة طلب، `returns` الاستبدال، `stock` التوفر والحجز، `other` موضوع آخر مدعوم |
| عائق ظهر بالفعل | `fit_unclear` توافق غير واضح، `product_missing` معلومة ناقصة، `checkout_failed` تعذر الطلب أو الدفع، `price_objection` اعتراض صريح على السعر، `stock_missing` عدم التوفر، `shipping_delayed` تأخر التجهيز أو الشحن، `shipping_unclear` موعد أو تكلفة غير واضحة، `return_blocked` تعثر الاستبدال |
| نقطة تدريب | `incomplete` إجابة غير مكتملة، `vague` إجابة تحتاج تحديدًا، `followup` متابعة تحتاج مراجعة |

السؤال «كم السعر؟» لا يتحول إلى «اعتراض على السعر»، والسؤال عن التوصيل لا يتحول وحده إلى تأخر شحن.

التصنيف الجديد يضاف عند استخدام زر **«حلّل الرحلة» يدويًا** لنسخة ليس لها تحليل محفوظ. يُحفظ في JSON النتيجة الموجود، مع ربط المراجع بمعرفات الرسائل ومقتطفاتها المنقحة. النتائج القديمة المحفوظة تُعاد كما هي من الكاش، دون إعادة تحليلها أو ترقيتها تلقائيًا. لم يتغير سقف الطلبات أو حد 700 رمز إخراج أو حد 8,500 بايت للطلب. قد يرفض حد الحجم مقتطفًا طويلًا قبل حجز أي طلب؛ لا يُرفع السقف لتمريره.

## ترتيب التحسينات

الاقتراحات إجراءات ثابتة مرتبطة بالعائق أو نقطة التدريب، وليست أوامر ينفذها النظام. تُقسم إلى مشكلة بالمتجر، وتشغيل أو شحن، وتدريب الموظف. الترتيب هو عدد المحادثات المختلفة، ثم عدد الرسائل المرجعية المتاحة في السجل الحالي، ثم المراجع المحفوظة عند التعادل. لا توجد نسبة ثقة مخترعة، ولا تتحول ملاحظات النموذج إلى تقييم نهائي للموظف أو سبب مؤكد لفقد البيع.

## نتائج الرحلة من بيانات سلة المحلية

| النتيجة | الدليل المطلوب |
| --- | --- |
| طلب مرتبط بتتبع | عميل مطابق بهاتف فريد؛ رمز مطابق في مصدر طلب سلة، وفي رابط متجر لنك داخل رسالة موظف مؤكد، وفي سجل نسخ سابق للرابط؛ الطلب بعد الرسالة ضمن 72 ساعة. الرمز المعاد استخدامه بين حالات مؤهلة لا يثبت محادثة بعينها. |
| طلب بعد المحادثة بتطابق الهاتف | عميل مطابق واحد وطلب صالح خلال 72 ساعة بعد رسالة عميل؛ لا يُنسب لتتبع أو لسبب شراء. |
| دعم لطلب سابق | عميل مطابق ومرجع الطلب نفسه مذكور صراحة في رسالة عميل بعد إنشاء الطلب. مجرد وجود طلب أسبق غير كافٍ. |
| غير مؤكدة | هاتف مفقود أو ملتبس، تعذر السجل، قراءة جزئية أو عدم وجود دليل كافٍ. لا تعني عدم الشراء. |

يُزال تكرار الطلب بالمعرف الخارجي في الفترة كلها. إذا اشترك بين حالات تُقدَّم مطابقة التتبع المثبتة، ثم أحدث رسالة مؤهلة؛ هذه قاعدة عد فقط لا إثبات سببية. يعرض ملخص كل محادثة أقوى نتيجة والطلبات التي تدعمها، وليس إجمالي كل مشتريات العميل. الطلب الملغى أو المرتجع لا يدخل كنتيجة شراء، ويمكن أن يكون موضوع دعم لطلب سابق.

الرحلة المنفردة تستخدم آخر 12 طلبًا كما كان سابقًا. إزالة التكرار **بين** المحادثات تكون في إحصائيات الفترة؛ نتيجة الرحلة المنفردة إشارة سياقية ولا تضاف للعداد عند كل فتح.

## الحدود والتشغيل

- قراءة من قاعدة البيانات المحلية عبر نقطة المدير الحالية: `GET /api/crm-admin?resource=service-monitor&view=insights&from=YYYY-MM-DD&to=YYYY-MM-DD`.
- حتى 5,000 رسالة و200 محادثة، مع صفحات قراءة محدودة و32 طلب قاعدة بيانات كحد أقصى. قراءة الطلبات محدودة، وتظهر حالات النقص بدل الجزم بمطابقة غير مكتملة.
- قراءة التحليلات وقراءة سلة مستقلتان عند الفشل. خطأ التحليلات لا يمحو وقائع الطلب المتاحة، وغياب سلة لا يمحو التحليلات.
- فتح الإحصائيات يقرأ مرة واحدة؛ «عرض الفترة» يعيد القراءة عند الطلب. بعد تحليل جديد يمكن الضغط عليه لتحديث الإحصائيات. لا polling أو cron أو مزامنة إضافية مع سلة، ولا OpenAI تلقائي أو رسائل للعملاء.
- لا هجرة SQL أو تعديل صلاحيات أو أسرار أو اتصال خارجي. التصنيفات الجديدة داخل `result` JSON الموجود.
- مؤشرات اليوم والشهر الأصلية وحساب انتظار الدوام 14:00–23:00 يوميًا بتوقيت السعودية كما هي.
